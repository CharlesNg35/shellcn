The model

Plugins declare. The core owns.

A plugin ships one versioned manifest (config schema, views, actions, streams, routes) plus typed route handlers. The core owns auth, sessions, transport, audit, and rendering — and serves the browser a projection of the manifest. The frontend renders that projection, so adding a protocol needs zero frontend changes.

BrowserUniversal renderer — ~20 panel types. Terminals, tables, trees, desktops.
Core gatewayAuthN/Z · RBAC · secrets · sessions · transport · audit · projection.
Plugins → targetsManifest + route handlers. Direct or reverse-agent transport.
One connection, many capabilities

Reach it all from one place.

Twenty protocols ship in the box. Add more as out-of-tree gRPC plugins or from the marketplace.

Secure & auditable from day one

Built like infrastructure, not a toy.

RBAC & ownership grants

Every route carries a permission and risk tier, enforced by Casbin plus per-connection ownership and sharing grants. Secrets are AES-256-GCM encrypted and write-only.

Session recording

Terminal sessions record as asciicast v2; remote desktops capture graphically. Plugin-declared, off by default, private to their creator.

Reach private networks

A tiny reverse-tunnel agent dials back from inside a target behind NAT or a firewall — transport is orthogonal to protocol, invisible to the plugin.

Single self-contained binary

Pure-Go dependencies, embedded Vue frontend, SQLite by default (Postgres/MySQL optional). Even RDP decodes in-process — no external daemon.

Browser-native everything

xterm.js terminals, noVNC desktops, CodeMirror editors, live metrics and log tails — all rendered from the manifest projection.

Extensible & audited

Out-of-tree plugins run as sandboxed gRPC subprocesses with no ambient authority. Every action is authn → authz → validate → audit → handler.

Run it

Up in one command.

Each needs a master key (it encrypts stored credentials) and a first admin login. Then open http://localhost:8081 and sign in.

docker run -d --name shellcn -p 8081:8081 \
  -v shellcn-data:/data \
  -e SHELLCN_MASTER_KEY="$(openssl rand -base64 32)" \
  -e SHELLCN_BOOTSTRAP_ADMIN_USERNAME=admin \
  -e SHELLCN_BOOTSTRAP_ADMIN_PASSWORD=change-me \
  ghcr.io/charlesng35/shellcn:latest
services:
  shellcn:
    image: ghcr.io/charlesng35/shellcn:latest
    ports: ["8081:8081"]
    environment:
      SHELLCN_MASTER_KEY: ${SHELLCN_MASTER_KEY}
      SHELLCN_BOOTSTRAP_ADMIN_USERNAME: admin
      SHELLCN_BOOTSTRAP_ADMIN_PASSWORD: change-me
    volumes: ["shellcn-data:/data"]
    restart: unless-stopped

volumes:
  shellcn-data:
export SHELLCN_MASTER_KEY="$(openssl rand -base64 32)"
export SHELLCN_BOOTSTRAP_ADMIN_USERNAME=admin
export SHELLCN_BOOTSTRAP_ADMIN_PASSWORD=change-me
./shellcn      # serves on :8081, data in the working dir

Reuse the same master key on restart, or stored credentials can't be decrypted. Data and recordings live in /data — mount a volume there.

Run it, open a browser, and you're in.
